RELATED DECISIONS & TRADEOFFS
───────────────────────────────────────────────────────────────────────────────

Decision: Use Pre-trained Model (Recycling-Net-11) vs. Train Custom
  ✅ Chose: Pre-trained
  Rationale: 
    • Meets accuracy requirement without work
    • Time to MVP: Ready now vs. 3-4 weeks for training
    • Risk reduction: Known baseline accuracy
    • Resource efficiency: No dataset needed
  Tradeoff: 1-2% accuracy improvement possible with training (deferred to Phase 2)

Decision: Model Size (Float32 vs. Float16 vs. Int8)
  ✅ Chose: Int8 for production (88 MB)
  Alternatives:
    • Float32: 200-350 MB (largest, reference baseline)
    • Float16: ~177 MB (middle ground)
    • Int8: 88 MB, best ANE support, <1% accuracy loss
  Rationale: App bundle size priority, ANE optimization priority

Decision: Conversion Path (Direct vs. ONNX Intermediate)
  ✅ Chose: PyTorch → ONNX → Core ML
  Rationale:
    • ONNX is standardized, widely supported
    • Easier debugging if issues arise
    • Can inspect/modify ONNX model if needed
    • coremltools has better ONNX support than direct conversion
